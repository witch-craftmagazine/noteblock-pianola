# Noteblock Pianola — Project Documentation

**Hosted at:** `https://witch-craftmagazine.github.io/noteblock-pianola/`  
**Brand name:** Noteblock Pianola
**Type:** Static single-page web app (no backend; `bun run build` bundles `src/musicbox/` before deploy)

---

## What It Is

An interactive 3D music box that plays MIDI files through a Minecraft-themed soundfont. The user winds a crank on a 3D model to trigger playback. Musical note glyphs float up as particles while the music plays. A full track list of ~278 MIDI files (ragtime, jazz, classical, broadway, bossa nova, etc.) can be browsed via a floating player UI at the bottom of the screen.

Easter egg overlays — full-screen animated scenes — are triggered by specific songs. Five currently exist, each in its own module under `easter-eggs/`.

There is also a second page, `no/index.html`, a horror-styled easter egg experience with its own assets, ambient sounds, and background panoramas.

## Architecture

The app has no framework, no bundler, and no server. Everything runs in the browser from static files served by GitHub Pages.

### Dependency loading order (index.html)

1. **Importmap** — maps bare specifier `spessasynth_core` to `./lib/spessasynth_core.js`. Must appear before any `<script type="module">`.
2. **Three.js r128** — loaded from cdnjs CDN.
3. **GLTFLoader** — loaded from jsDelivr CDN (Three r128 build).
4. **Inline script block 1** — Scene setup, GLB loading, animation system, crank/lid interaction, music callbacks, background toggle.
5. **Inline script block 2** — Note particle system (canvas overlay).
6. **`<script type="module" src="./script.js">`** — MIDI player.
7. **`<script type="module" src="./easter-eggs/egg-loader.js">`** — Loads `registry.json` and dynamically imports each egg module.

### Global communication pattern

Because `script.js` and `egg-loader.js` are ES modules and the inline scripts are classic scripts, they communicate through `window` globals:

| Global | Set by | Read by |
|--------|--------|---------|
| `window.musicPlayer` | `script.js` | `index.html` crank handler |
| `window.onMusicPlay(songFile)` | chain of IIFEs wrapping each other | each subscriber |
| `window.onMusicPause()` | same chain | same |
| `window.onMusicEnd()` | same chain | same |
| `window._currentSong` | `script.js` | egg modules (check filename against trigger) |
| `window._sf2Buffer` | `script.js` init | `ensureAudioContext()` |
| `window.musicBoxAnimations` | inline script 1 | music callbacks |
| `window._registerCrankMeshes(root)` | inline script 1 | called during GLB load |
| `window._registerLidMeshes(root)` | inline script 1 | called during GLB load |

Each subscriber hooks into `onMusicPlay/Pause/End` by saving the previous value and wrapping it — forming a chain. The ordering of the `<script>` blocks determines the chain order.

## Systems in Detail

### 1. Three.js Scene

Renders `musicbox.glb` into a full-viewport canvas (`#three-canvas`). Camera is fixed at a 30° horizontal offset, aimed at y=0.5. Four-light rig: ambient (warm), key (directional + shadow), fill, rim. Shadow map 1024×1024, PCFSoft.

`CONFIG` at the top of inline block 1 exposes tunable values: camera distance/height, light intensities, drag sensitivity, and wind threshold.

### 2. Animation System

Four named clips expected in the GLB:

| Clip name | Purpose |
|-----------|---------|
| `crank_spin` | Looping crank rotation during playback |
| `idle` | Looping ambient idle motion during playback |
| `open` | One-shot lid opening |
| `close` | One-shot lid closing |

`lid/top/cover` tracks are stripped from `crank_spin` and `idle` at load time so those loops can't fight the open/close clips. A queued-open guard handles the case where `open` is requested while `close` is still mid-play.

### 3. Crank Interaction — **Mouse Only (Touch Not Yet Wired)**

- `mousedown` on a crank mesh starts a drag session and pauses current playback.
- `mousemove` during drag accumulates wind in pixels. Vertical drag (abs value) and leftward horizontal drag both count; the dominant axis wins to avoid double-counting diagonal motion.
- `mouseup` checks accumulated wind against `CONFIG.WINDS_TO_PLAY × CONFIG.DRAG_PX_PER_REV`. If the threshold is met, `window.musicPlayer.play()` fires.
- `mousedown` on a lid mesh toggles the open/close animation.

**There are no `touchstart`, `touchmove`, or `touchend` handlers.** Touch appears to work in browsers that emulate mouse events from touch, but this is incidental and unreliable. Explicit touch support is a remaining priority — see Improvement Opportunities.

### 4. MIDI Player (script.js)

- Fetches `midilist.json`, populates track metadata array with title/artist/year parsed from filenames.
- Fetches `soundfonts/manifest.json`, then the user's saved (or default) soundfont from `soundfonts/`; stores the buffer on `window._sf2Buffer` if no `AudioContext` exists yet, otherwise registers it live via `synth.soundBankManager`. The pick persists in `localStorage` (`noteblock-pianola:soundfont`) and is switchable at runtime via `window.musicPlayer.setSoundfont(id)` — see `src/musicbox/soundfont-toggle.js` for the button/dropdown UI.
- Fetches `volumeAdjustments.json` — per-track loudness multipliers derived from `tools/analyze-loudness.js`.
- `AudioContext` created lazily on first user gesture.
- Uses SpessaSynth's `WorkletSynthesizer` and `Sequencer`. `seq.loop = false` — on `seq.isFinished`, auto-advances to next track.
- Starts on a random track at page load.
- Exposes `window.musicPlayer` with `play()`, `pause()`, `next()`, `prev()`, `shuffle()`, `isPlaying()`.
- Volume stored as a slider position (0–1), converted to gain via a 4th-power curve for perceptual linearity.
- Master gain = `sliderToGain(sliderPos) × currentTrackGain` (track gain from `volumeAdjustments.json`).
- A short `click.ogg` plays on every button press, loaded lazily after `AudioContext` creation.

Player UI (`#music-player`) is built entirely in JS and appended to `<body>`: dark frosted-glass panel at bottom-center with track name, transport controls, seek bar, volume slider, sortable/searchable track dropdown, and status line.

### 5. Note Particle System

A 2D canvas overlay (`#note-canvas`) drawn on every animation frame. While playing, a note glyph (♩ ♪ ♫ ♬) spawns every ~400ms (25% chance of double-spawn). Each particle drifts upward with horizontal wobble, fades out, and is drawn with a glow shadow. Colors come from a 13-stop rainbow palette, blended 65% toward white so they're not fully saturated.

### 6. Easter Egg System

**Architecture:** `egg-loader.js` fetches `easter-eggs/registry.json` and dynamically `import()`s each egg's module. Each module exports `init({ trigger })` and is fully self-contained.

**Current registry (`easter-eggs/registry.json`):**

| id | trigger song | module |
|----|-------------|--------|
| `minecraft` | `i_feel_pretty_1957_-_bernstein` | `./minecraft/index.js` |
| `carrotfield` | `dixieland_delight_1983_-_rogers` | `./carrotfield/index.js` |
| `green` | `greensleeves_1500s_-_traditional` | `./green/index.js` |
| `office` | `the_office_theme_2011_-_ferguson` | `./office/index.js` |
| `lab` | `hip_to_be_square_1986_-_lewis` | `./lab/index.js` |

**Egg module contract:** Each module exports `init({ trigger })` which:
1. Creates its own DOM overlay element and appends it to `document.body`.
2. Hooks into `window.onMusicPlay/Pause/End` using the wrap-and-chain pattern.
3. Shows itself only when `window._currentSong` matches its `trigger`.
4. Cleans up (hides renderer loop) on pause/end.

Each egg is fully self-contained — its own renderer, scene, and assets. The loader does not know what the egg renders.

**Adding a new egg:**
1. Create `easter-eggs/[name]/index.js` exporting `init({ trigger })`.
2. Add one entry to `registry.json`.
3. No changes to `index.html` or any other file.

### 7. `no/` — Horror Page

`no/index.html` is a self-contained horror-styled secondary page. It has its own Three.js scene, CRT-styled 4:3 viewport, and references these assets (all relative to the repo root):

| Asset | Path |
|-------|------|
| Jump scare audio | `../scare.mp3` |
| Ambient heartbeat | `../heartbeat.mp3` |
| Ambient rain | `../rain.mp3` |
| Monster image | `../monster.png` |
| Background panoramas | `../piano/panorama_*.webp` |

The page was previously `no.html` at the repo root and has been moved to `no/index.html` so it is served at `/no/` — a cleaner URL with no `.html` extension visible. All internal asset references use `../` to reach root-level files. No other page links to it directly; it is an intentionally hidden experience.

## Mobile Layout

Both `index.html` and `no/index.html` include:

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0, maximum-scale=1.0, user-scalable=no">
```

This prevents pinch-zoom on mobile.

`index.html` layout CSS:

- `body` — `display: flex; align-items: center; justify-content: center; touch-action: none; overflow: hidden`
- `#canvas-container` — `width: 100%; height: 100%; position: relative; display: flex; align-items: center; justify-content: center; overflow: hidden`
- `canvas` — `width: 100% !important; height: 100% !important; max-width: 100vw; max-height: 100vh; object-fit: contain`

This ensures the 3D scene and all absolute-positioned overlays (easter eggs, note particles) fill and center correctly on any screen size, including narrow mobile viewports. The Three.js renderer resize handler uses `container.clientWidth/clientHeight`, which correctly tracks the flex container's actual dimensions.

## Dev Utilities

### `tools/sync.js` — full add-a-song pipeline

Runs all three steps in sequence. Use this every time you add songs:

```
node tools/sync.js            # incremental (only analyzes new tracks)
node tools/sync.js --full     # re-analyzes every track (run after adding a batch)
```

Then commit:
```
git add midi/ midilist.json song/ volumeAdjustments.json
git commit -m "Add new song(s)"
git push
```

### `tools/rebuild-midilist.js`

Rescans `./midi/*.mid` and rewrites `midilist.json` sorted alphabetically. Reports added/removed tracks. Safe — refuses to write an empty list.

```
node tools/rebuild-midilist.js
```

### `tools/generate-share-pages.js`

Generates `song/<slug>/index.html` for every track in `midilist.json`. Each page carries per-song Open Graph/Twitter meta tags (so Discord, iMessage, etc. show the song title) then immediately redirects to `/?song=<slug>`.

```
node tools/generate-share-pages.js
```

### `tools/analyze-loudness.js`

Renders each MIDI headlessly through SpessaSynth, measures RMS loudness, and writes per-track gain multipliers to `volumeAdjustments.json` (ReplayGain-style normalization). Requires `soundfonts/minecraft3.sf2` to be present — **not run in CI** because the soundfont is too large for the repo. Incremental by default.

```
node tools/analyze-loudness.js            # incremental
node tools/analyze-loudness.js --full     # re-analyze everything
```

### `scripts/name.py`

Normalizes all filenames in `./midi/` to lowercase/underscores, detects collisions, and rebuilds `midilist.json`. Run manually or triggered automatically by CI on push to `midi/`.

```
pip install mido
python scripts/name.py
```

### `scripts/inst.py`

Scans all MIDI files and prints each file's MIDI program-change instrument count, sorted descending.

```
pip install mido
python scripts/inst.py
```

## CI / GitHub Actions

### `.github/workflows/update-midilist.yml`

Triggers on any push to `main` that touches `midi/**`, and can also be triggered manually from the Actions tab.

**Steps:**
1. `scripts/name.py` — normalizes filenames, exits with error on collision
2. `tools/rebuild-midilist.js` — verifies `midilist.json` is in sync
3. `tools/generate-share-pages.js` — regenerates all `song/` OG preview pages
4. `stefanzweifel/git-auto-commit-action` — commits `midilist.json`, `midi/**`, and `song/**` back to `main`

`static.yml` then picks up the auto-commit and deploys to GitHub Pages.

**Not in CI:** `analyze-loudness.js` requires `soundfonts/minecraft3.sf2` which is not stored in the repo. Run it locally via `node tools/sync.js` and commit `volumeAdjustments.json` manually when adding new tracks.

### `.github/workflows/static.yml`

Deploys the repo to GitHub Pages on every push to `main`.

## Deployment

GitHub Pages serves the repo root as static files. No build step, no CI configuration beyond the two workflows above.

**Initial setup (one time):** Repo Settings → Pages → Deploy from branch → `main` / `/ (root)`.

**Every subsequent deploy:** `git push` to `main`. GitHub rebuilds within ~30–60 seconds.

**MIME types:** GitHub Pages correctly serves `.js`, `.json`, `.sf2`, `.glb`, and `.mid` without configuration. Native ES module imports work as-is.

**CORS:** All assets are same-origin on GitHub Pages, so `fetch()` calls for all asset types succeed without any headers configuration.

## Adding a New Song — Full Workflow

```bash
# 1. Drop the .mid file into midi/
cp my_song.mid midi/

# 2. Run the full pipeline locally
node tools/sync.js         # normalizes name, rebuilds midilist, generates share page, analyzes loudness

# 3. Commit everything
git add midi/ midilist.json song/ volumeAdjustments.json
git commit -m "Add: my_song"
git push
```

CI will normalize filenames and regenerate share pages again on push, which is harmless and acts as a safety net if you forgot step 2.

## Improvement Opportunities

### Priority 1 — Explicit Touch/Pointer Events for Crank

**Problem:** Crank interaction is wired to `mousedown/mousemove/mouseup` only. Touch works incidentally in browsers that synthesize mouse events, but is unreliable — scroll hijacking, no pointer capture, no multi-touch guard.

**Fix:** Replace the three mouse handlers in inline block 1 with `pointerdown/pointermove/pointerup` (Pointer Events API). One code path covers mouse, touch, and stylus.

Key details:
- `canvas.setPointerCapture(e.pointerId)` on pointerdown keeps pointermove firing even if the finger drifts off the canvas.
- `touch-action: none` is already set on `body`; also set it on `#three-canvas` explicitly.
- Skip cursor style changes when `e.pointerType === 'touch'`.
- `e.clientX/clientY` is identical to mouse — raycaster logic needs no changes.

### Priority 2 — Module Refactor of index.html

**Problem:** `index.html` contains the entire scene, animation, crank, and particle systems inline (~1000+ lines). Hard to navigate and diff.

**Approach:** Move inline blocks into `src/` ES modules — no bundler needed, GitHub Pages serves `.js` with correct MIME type.

```
src/
  scene.js          ← Three.js scene, lighting, model load, resize
  animations.js     ← musicBoxAnimations object, mixer, clip logic
  interaction.js    ← pointer events (crank drag, lid click, hit test)
  particles.js      ← note particle canvas system
  callbacks.js      ← onMusicPlay/Pause/End base implementations
  bg-toggle.js      ← background toggle button
```

The global communication contract (`window.musicPlayer`, `window.onMusicPlay`, etc.) stays unchanged.

### Lower Priority

- **Vendor Three.js** — copy `three.min.js` and `GLTFLoader.js` into `lib/` to eliminate the CDN dependency.
- **Loading progress bar** — stream the soundfont fetch with `response.body` + `ReadableStream` and show byte progress.
- **Persist preferences** — store background-toggle state and volume in `localStorage`, restore on load.
- **Keyboard shortcuts** — spacebar for play/pause, arrows for prev/next.
- **`?song=` deep link** — start playback of a specific track on page load (pairs with the share pages already generated by `generate-share-pages.js`).
